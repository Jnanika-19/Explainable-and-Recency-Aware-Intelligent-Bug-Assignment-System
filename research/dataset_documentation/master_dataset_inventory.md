# Master Eclipse Dataset Inventory

Inventory date: 2026-11-11

## Scope and evidence

Project root: repository root (`.`).

This inventory records the current local dataset layout and existing collection
reports. JDT CSV sizes, row counts, headers, and checksums below come from
[`dataset_availability.md`](./dataset_availability.md), which was generated
from local files on 2026-11-11. Counts are data rows, excluding CSV headers.
The raw JDT export was not row-counted in that report. Its exact listed size is
6,377,569,970 bytes (about 5.94 GiB); the source report's prose describes it as
about 6.08 GiB, which is inconsistent with its tabulated 6,082.12 MiB size.
JDT counts and checksums were not recomputed here. Repository commit/ref counts
come from the corresponding collection reports, except JDT, which is covered
only by the dataset availability report. The separately approved combined Git
extraction is documented in
[`eclipse_git_extraction_report.md`](../../dataset/processed/cold_start/eclipse_all_repositories/eclipse_git_extraction_report.md);
its outputs were independently checked after generation.

Feature abbreviations: **E** expertise, **R** recency, **W** workload,
**X** explainability, **C** cold-start, **A** adaptive feature selection,
**P** prediction confidence, **D** duplicate/related bugs, **K** Top-K ranking.
Support means data may contribute to future implementation, not that the
feature or model is complete.

The candidate source contains 14,037 rows. The manual review queue groups
duplicate evidence reasons into 12,715 unique cross-repository pairs; 1,322
pairs occur in both evidence queues. Of the unique pairs, 31 exact-email
matches have no exact normalized-name match, and 12,576 pairs involve at
least one identity with multiple candidate links. These are ambiguity flags,
not adjudication outcomes. See `identity_review_summary.md` and
`identity_review_queue_addendum.md` in the same folder for the full review
guidance.

The generated files total 750,478,237 bytes (about 715.5 MiB). Independent
checks found no missing required fields, duplicate commit keys, orphan path
rows, duplicate repository/author roster keys, or invalid identity-candidate
references. Optional blanks remain in the evidence: 5,349 commit author emails,
2 commit subjects, and 7 roster component lists are blank; the corresponding
per-file blanks repeat commit metadata (22,482 blank email cells and 1,062
blank subject cells). These are not treated as extraction failures.

The combined JDT contribution file has 312,493 path rows versus 279,322 in the
pre-existing JDT-only output. The new extractor explicitly records first-parent
merge diffs, while the old script did not specify a merge-diff policy. Preserve
both outputs; the row-count difference is a methodology/provenance distinction,
not evidence that the old JDT file was replaced.

## Current organization and inconsistencies

- The dataset currently contains JDT Bugzilla raw/processed data and five
  external Git repositories. No Platform/PDE Bugzilla reports or assignment
  labels were collected; all non-JDT evidence is Git history only.
- Local `.gitignore` rules exclude `dataset/raw/*`, `dataset/processed/*`,
  and `dataset/external/*`; large datasets and Git histories are therefore
  ignored by Git. No ignore-rule change is proposed.
- The new combined-output directory is separate from all existing JDT outputs
  and is covered by the existing `dataset/processed/*` ignore rule.
- Four of five repositories have standalone collection reports. JDT does not;
  its count and partial-clone/checkout caveats are in the availability report.
