## Shared coordination: Top-K and overall integration

All members coordinate against the candidate key `(bug_id, developer_id)` and bug-level cutoff/split. Preserve every candidate row for a bug in the same split. Targets and evaluation-only fields must remain separate from predictors. Agree on:

1. a common per-candidate evidence/status contract;
2. missing and unsupported evidence semantics (unknown is not zero);
3. eligibility handling for out-of-pool targets;
4. a Top-K interface that consumes member outputs without using target labels as features; and
5. repository-scoped identity boundaries.

The current data are inputs for future implementation, not evidence that the recommendation system or any feature has been evaluated.
